  • 1. Data Ingestion: Proses pengumpulan dan penyerapan data mentah dari berbagai sumber (database relasional, sensor IoT, API, log server) baik secara batch maupun real-time.
  • 2. Data Storage: Penyimpanan data ke dalam wadah yang sesuai dengan karakteristiknya (Data Lake / HDFS untuk data tidak terstruktur/mentah, dan Data Warehouse untuk data terstruktur yang terkurasi).
  • 3. Data Processing: Proses transformasi, pembersihan (cleansing), integrasi, dan komputasi data skala besar menggunakan ekosistem terdistribusi (seperti MapReduce atau Apache Spark).

Esai 4 - Gambar Arsitektur (Shape)
4. Gambarkan arsitektur Apache Flume (baik Single Agent maupun pola Multi-Agent Consolidation) lengkap dengan komponen di dalamnya, serta jelaskan perbedaan fungsi antara Apache Kafka, Apache Flume, dan Apache Sqoop!

Kunci Jawaban Referensi (Materi Data Acquisition):

[Web Server] ──(Event)──► ┌──────────────────────────────────────────┐ │ FLUME AGENT │ │ [Source] ──► [Channel] ──► [Sink] │ ──► [HDFS / Storage] └──────────────────────────────────────────┘ *Arsitektur Consolidation (Multi-Agent): [Agent 1: Avro Sink] ──┐ [Agent 2: Avro Sink] ──┼──► [Agent 4: Avro Source -> Channel -> Avro Sink] ──► [HDFS] [Agent 3: Avro Sink] ──┘
  • Komponen Flume Agent: Source (menerima event dari sumber eksternal), Channel (penampung antrean sementara seperti Memory/File Channel), dan Sink (meneruskan event dari Channel ke HDFS atau Agent lain).
  • Perbedaan Kafka vs Flume vs Sqoop:
    • Apache Kafka: Platform distributed streaming berbasis mekanisme Publish-Subscribe (menggunakan Producer, Broker, Topic, Partition, dan Consumer dengan sistem tarik/pull) yang cocok untuk pemrosesan aliran data real-time berkecepatan tinggi.
    • Apache Flume: Dirancang khusus untuk mengumpulkan, menggabungkan, dan memindahkan data log atau streaming (seperti log web server atau media sosial) secara langsung ke penyimpanan terpusat seperti HDFS atau HBase.
    • Apache Sqoop: Berfokus pada transfer data massal (bulk import/export) dua arah antara database relasional (RDBMS seperti MySQL/Oracle) dengan ekosistem Hadoop (HDFS, Hive, HBase) menggunakan tugas Map paralel dan driver JDBC.
Esai 5 - Gambar Arsitektur & Alur (Shape)
5. Gambarkan skema mekanisme operasi tulis (Write) pada Apache HBase mulai dari Client mengirimkan perintah Put hingga data tersimpan permanen di HDFS, dan jelaskan peran ZooKeeper, WAL, MemStore, serta HFile!

Kunci Jawaban Referensi (Materi Big Data Storage - HBase):

[Client] ──(Cek lokasi .META)──► [ZooKeeper] │ └──(1. Put Request)──► [Region Server] │ ┌─────────────────────┴─────────────────────┐ ▼ ▼ (1) Tulis ke [WAL / HLog] (2) Salin ke [MemStore] (Log pemulihan di HDFS) (Write Cache di Memori) │ ├──► (3) Kirim ACK ke Client ▼ (4) Flush saat penuh (Threshold) ke [HFile] di [HDFS DataNode]
  • ZooKeeper: Layanan koordinasi terdistribusi yang memantau status hidup server (melalui heartbeat dan ephemeral node), memilih Active HMaster, serta menyimpan lokasi Region Server yang menampung tabel katalog .META.
  • WAL (Write Ahead Log / HLog): File log tempat data baru pertama kali dicatat sebelum masuk ke memori. Berfungsi untuk memulihkan data (recovery) apabila Region Server mengalami gangguan sebelum data di memori ditulis ke disk.
  • MemStore: Write cache di memori utama (terdapat satu MemStore untuk setiap Column Family dalam satu Region). Segera setelah data masuk ke MemStore, HBase mengirimkan konfirmasi berhasil (ACK) ke Client.
  • HFile: File penyimpanan permanen di HDFS DataNode. Ketika ukuran MemStore mencapai batas ambang (threshold), seluruh isinya di-flush ke disk menjadi HFile yang terurut berdasarkan KeyValue.
